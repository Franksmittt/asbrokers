1. WHAT IT IS AND WHY IT EXISTS
================================================================================

Blog Studio is AS Brokers' bespoke content management system for publishing
financial education articles on the public website. It lives at:

  /studio/blog

It is NOT Sanity CMS. Sanity was fully removed; Insights are Studio-only
(see docs/TASK12-STUDIO-ONLY-INSIGHTS.md and docs/TASK13-SANITY-DEAD-CODE.md).

THE IDEA BEHIND IT
------------------
AS Brokers publishes long-form, compliance-aware articles on retirement,
insurance, estate planning, Everest Wealth, and related topics. The owner
(Albert) works with AI tools (ChatGPT, Claude, Gemini) to draft HTML article
content, then uses Blog Studio to:

  1. Paste and refine HTML in a guided 5-step workflow
  2. Upload images in visual order (replacing placeholders)
  3. Optionally embed calculators and videos
  4. Set categories, SEO metadata, and hero image
  5. Publish to the live site at /insights and /insights/[slug]

The studio is designed for a non-developer owner:
  - Access via Studio password OR CRM staff PIN/session (Command Workspace bridge)
  - Visual publish-readiness checks (percentage + "Next fix")
  - Built-in brand guide and AI prompt templates
  - Markdown or warm HTML paste; dark night-mode markup blocked at publish
  - Work-in-progress saved in browser localStorage (7-day TTL)

PUBLIC OUTPUT
-------------
Published posts appear on:
  - /insights          — feed with category and date filters
  - /insights/[slug]   — full article page
  - /sitemap.xml       — published studio slugs included
  - Homepage teaser    — static marketing teasers (not live-fetched on /)

Articles render stored sanitized HTML (body_html_published) with support for
embedded calculators (iframe to /embed/calculators/*), YouTube/Vimeo iframes,
and inline scripts where allowed by the sanitizer.

3. THE 5-STEP OWNER WORKFLOW
================================================================================

Step 1 — Start a post
  Create title + URL slug (lowercase, hyphens). Save draft.

Step 2 — Add article content
  Paste AI-generated HTML. Use Auto-fix when offered. Save draft.
  Placeholders supported:
    [IMAGE_SLOT]           — primary image placeholder
    [CALCULATOR_SLOT]      — calculator embed slot
    [VIDEO_SLOT]           — video embed slot
  Legacy tokens also accepted: YOUR_IMAGE_URL_HERE, {{IMAGE_URL}}, etc.

Step 3 — Add images
  Upload images in visual order (top to bottom in article).
  Client-side optimization before upload (~900KB max, 1600px max side).
  Hero image URL required before publish (auto or manual).

Step 4 — Post details + categories
  Select one or more insight categories (required for publish).
  Set excerpt, meta title, meta description.
  Review publish-readiness percentage and "Next fix" hints.

Step 5 — Review & publish
  Publish now → server validates → sanitizes HTML → sets status=published.
  Publish report shows route and image health checks.
  On hard failure (empty HTML, unresolved slots): auto-reverts to draft.

UNPUBLISH / DELETE
------------------
  Unpublish  — reverts to draft, clears body_html_published and published_at
  Delete     — permanent row removal
  Delete all — requires CLIENT_STUDIO_ENABLE_BULK_DELETE=true + typing DELETE ALL

4. DATABASE — client_insight_posts
================================================================================

PRIMARY TABLE: client_insight_posts (PostgreSQL on Supabase)

COLUMN                  TYPE        PURPOSE
--------------------------------------------------------------------------------
id                      uuid PK     Unique post ID
slug                    varchar     URL segment (/insights/[slug])
locale                  varchar     en | af (unique with slug)
title                   text        Article title
excerpt                 text        Feed card summary
body_html               text        Last saved editor HTML (may have placeholders)
body_html_published     text        Sanitized HTML served publicly when published
status                  varchar     draft (default) | published
categories              jsonb       Array of category value strings
meta_title              text        SEO title override
meta_description        text        SEO description override
hero_image_url          text        Required for publish; insights thumbnail
calculator_name         text        Optional embedded calculator label
calculator_code         text        Optional calculator metadata
published_at            timestamptz When first/last published
created_at              timestamptz Row created
updated_at              timestamptz Last save

UNIQUE INDEX: (slug, locale) — one post per slug per language.

SECONDARY TABLE: studio_notebook_notes
  Private owner scratchpad (not public). Same Drizzle schema file.

5. IMAGE UPLOADS (SUPABASE STORAGE)
================================================================================

BUCKET: blog-images (private)
  Override: SUPABASE_BLOG_IMAGES_BUCKET env var
  Auto-created by ensureStudioBlogImagesBucket() via service role
  Limits: 20MB, jpeg/jpg/png/webp

UPLOAD PATHS
------------
  1. Primary (browser): POST /api/studio/upload/auth → signed URL → browser
     uploads directly to Supabase → returns proxy URL
  2. Alternate: uploadStudioImage server action or POST /api/studio/upload

SERVING (public proxy — bucket stays private)
---------------------------------------------
  GET /api/studio/media?bucket=blog-images&path=studio/YYYY-MM-DD/uuid.ext
  No session required. 1-year cache headers.
  Published HTML references /api/studio/media?... not raw Supabase URLs.

IMPORTANT: Removing an image slot in the editor clears the assignment in HTML
only — it does NOT delete the storage object.

KEY FILES
---------
  app/api/studio/upload/route.ts
  app/api/studio/upload/auth/route.ts
  app/api/studio/media/route.ts
  lib/client-studio/studio-storage.ts

7. HTML SANITIZATION AND METADATA
================================================================================

SANITIZER: lib/client-studio/sanitize-body.ts (sanitize-html library)

Applied on:
  - publishStudioPost
  - saveStudioPost when post is already published (live body updated)

Public pages serve stored body_html_published — NOT re-sanitized on read.

Allows: sections, headings, tables, iframes (YouTube/Vimeo + /embed/calculators/),
forms/inputs, script (with attribute allowlist). Strips dangerous protocols.

EMBEDDED METADATA IN SAVED HTML
-------------------------------
  <!--studio_meta:{rawHtml, imageUrls, calcSelection, videoUrls}-->
    — slot state for editor reload
  <!--studio_categories:[...]-->
    — category fallback when DB column missing

PUBLIC RENDERING
----------------
  components/client-studio/ClientInsightArticle.tsx   — article shell + JSON-LD
  components/client-studio/ExecutableArticleHtml.tsx  — renders published HTML;
    re-executes inline <script>; binds #everest-income-calculator

8. FLOW FROM STUDIO TO PUBLIC SITE
================================================================================

  Owner edits in BlogStudioClient
       ↓
  saveStudioPost / publishStudioPost (Server Actions in actions.ts)
       ↓
  Zod validation (postBaseSchema)
       ↓
  studio-posts-write → Postgres (or Supabase REST fallback)
       ↓
  publish: sanitizeInsightBody → body_html_published, status=published
       ↓
  revalidatePath /, /insights, /insights/[slug]
       ↓
  verifyPublishedHtmlHealth (HEAD images, fetch live /insights/slug)
       ↓
  Public:
    getInsightFeed() → listPublishedStudioPosts()
    /insights/[slug] → getPublishedStudioPostBySlug() → ClientInsightArticle

URL pattern: insightUrlPath(slug, locale) → /insights/{slug} or ?locale=af

NOTE: lib/insights/feed.ts is Studio-only. Sanity merge was removed.

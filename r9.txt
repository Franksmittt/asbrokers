TASK 1 — CRYPTOGRAPHIC SECURITY AUDIT
================================================================================

1.1 RAW BODY BEFORE JSON PARSE — CONFIRMED ENFORCED (PASS)
----------------------------------------------------------
app/api/webhooks/whatsapp/route.ts POST sequence:
  1. const rawBody = await request.text();
  2. verifyMetaWebhookSignature(rawBody, ...)
  3. parseMetaWebhookPayload(rawBody) — JSON.parse only after verify

- No request.json() before signature check.
- Next.js 15 Route Handlers do not auto-parse body.
- middleware.ts does not touch request body.

1.2 TIMING-SAFE HMAC COMPARISON — CONFIRMED (PASS)
--------------------------------------------------
lib/whatsapp/meta-webhook.ts:
- createHmac("sha256", appSecret).update(rawBody, "utf8")
- X-Hub-Signature-256: strips "sha256=" prefix
- Buffer.from(hex) + timingSafeEqual on equal-length buffers
- Malformed hex caught in try/catch → false

1.3 SECONDARY SECURITY OBSERVATIONS
-----------------------------------
- GET hub.verify_token uses === (not timing-safe) — Low, acceptable for subscribe
- Missing META_APP_SECRET returns 500 — Low, config leak
- Valid signature + bad JSON returns 400 — Low
- No object === "whatsapp_business_account" check — Low
- Trigger failures only logged in development — Medium, silent prod loss

TASK 2 — ASYNC HANDOFF & IDEMPOTENCY AUDIT
================================================================================

2.1 NON-BLOCKING HANDOFF TO META — CONFIRMED (PASS)
---------------------------------------------------
- void tasks.trigger(...) — no await on trigger
- return new Response("OK", { status: 200 }) immediately
- Meta timeout risk from blocking: none

Caveat: TRIGGER_SECRET_KEY missing → trigger fails async, Meta still gets 200,
messages lost without Meta retry.

2.2 IDEMPOTENCY KEY MAPPING — CONFIRMED (PASS)
----------------------------------------------
Meta message.id (wamid)
  → extractWhatsappInboundMessages messageId
  → tasks.trigger(..., { idempotencyKey: message.messageId })

Prevents duplicate Trigger task runs on Meta webhook retries.

2.3 IDEMPOTENCY GAPS (DATA LAYER) — PARTIAL
-------------------------------------------
- No external_message_id on correspondence — no DB audit trail
- No unique constraint on inbound WhatsApp message ID
- Trigger idempotency window expiry + late Meta retry → duplicate rows possible
- Worker retry.maxAttempts: 5 — insert success + crash before ack → duplicate risk
- Outbound sendWhatsAppMessage has no idempotency — double UI submit duplicates

TASK 3 — DRIZZLE JSONB PHONE QUERY LOGIC
================================================================================

3.1 HOW MATCHING WORKS
----------------------
sanitizePhone (lib/whatsapp/phone.ts):
  raw.replace(/\D/g, "") — digits only

Inbound:
  Meta message.from → sanitized in extractWhatsappInboundMessages
  Worker re-sanitizes payload.from
  DB: leadPhoneMatches(sanitizedPhone)
    regexp_replace(coalesce(raw_payload->>'phone',''), '[^0-9]', '', 'g') = $phone

Outbound:
  Load lead by UUID → phoneFromRawPayload(raw_payload) → sanitizePhone → Graph API

Both paths use digits-only equality — structurally consistent on happy path.

3.2 FRAGILITY — FLAGGED (CONDITIONAL PASS)
------------------------------------------
Issue                              Severity  Detail
-----                              --------  ------
SA local vs international format   HIGH      Meta sends 27…; funnel may store
                                             066… → 0662276044 ≠ 27662276044
No canonical phone column          Medium    Unstructured JSONB, no key enforcement
No index on raw_payload->>'phone'  Medium    regexp_replace = seq scan at scale
Multiple leads same phone          Medium    limit(1) no ORDER BY — arbitrary row
Single key "phone" only            Low       mobile/whatsapp keys won't match
Missing raw_payload.phone          Medium    lead_not_found, silent drop
assigned_advisor → auth.users      Low       Mock CRM uses staff table (s1, s2)

3.3 OUTBOUND INTEGRITY GAP
--------------------------
Graph API success then DB insert fails → message delivered, not in CRM.
No outbox / pending row pattern.
